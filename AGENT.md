# Houseforce Agent Context & Rules

## Project Overview
Houseforce is a digital ecosystem for a construction company, consisting of a public marketing web presence and a secure Customer Portal. 

## Architecture
- **Backend (`/backend`)**: Strapi CMS acting as the headless API and the single source of truth.
- **Frontend (`/frontend`)**: Next.js application serving both the public site and the secure customer portal.
- **Infrastructure**: Hosted on Digital Ocean. Orchestration is managed in a separate repository (`houseforce-infra`) using a single Traefik + Watchtower `docker-compose.yml` pattern, deploying via GHCR webhooks. 
- **Environments**: The Test environment uses local Postgres and Docker volumes. The Production environment uses Digital Ocean Managed Postgres and DO Spaces (S3) for media.

## Backend (Strapi) Specifics
- **Data Scoping**: Customers can only see their assigned data. This is strictly enforced via custom controller overrides (`src/api/*/controllers/*.ts`) that intercept API queries and apply filters using `ctx.state.user.id`.
- **Content Types**: 
  - `Project`: Linked Many-to-Many with `plugin::users-permissions.user`.
  - `Update`: Linked Many-to-One with `Project`.
- **TypeScript**: The backend uses strict TypeScript. When creating new content types, **always** ensure types are generated by Strapi so compilation does not fail. Do not cast to `any`.

## Frontend (Next.js) Specifics
- **Authentication**: Managed via `NextAuth.js`.
- **SSO Workflow**: We use an "Invitation-Only" Google SSO flow. Business owners manually create users in the Strapi Admin panel using the customer's Google email and link their projects. NextAuth handles the Google OAuth login, matches the email in Strapi, and retrieves a JWT scoped to that user.

## Critical Agent Rules
1. **Post-Change Verification**: After EVERY code change, you MUST run linting (`npm run lint`) and any available tests in the directory you modified (`backend` or `frontend`). Never skip this step.
2. **Avoid "Hacks"**: Fix TypeScript errors properly rather than using `as any` or `@ts-ignore`.
3. **Data Security**: Whenever fetching or mutating data in the backend, always rigorously verify the multi-tenant scoping rules. Customers must NEVER be able to access another customer's projects, updates, or invoices.
